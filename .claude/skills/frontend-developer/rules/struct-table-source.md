# Table Source Configurations

Tables in this application are dynamically generated based on configuration arrays (e.g., `src/config/models/table-source/ingredient.jsx`). These configurations map backend response properties directly to visual columns and determine advanced formatting behaviors as well as search capabilities.

## 1. Basic Columns definition

Each standard column must export an object containing at minimum the `key` (matching the exact property name in the API JSON) and a user-friendly `label` string:

```javascript
export default [
  {
    key: "name",
    label: "Name",
  },
  {
    key: "stock",
    label: "Stock",
  },
];
```

## 2. Dynamic Search Configuration (`searchable` & `type`)

To allow the frontend to dynamically construct search query objects for backend filtering across multiple fields, you must explicitly declare which columns are searchable.

Do not hard-code conditional search arrays inside `<DataTable />` or Page components. You **must always** add `searchable: true` and a predictable `type` (`"string"`, `"number"`) to any column that corresponds to text/string or numerical values. This rule applies to all such columns by default to ensure maximum, automatic search capability throughout the platform.

The `buildTableSearchQuery` helper will automatically iterate over all `searchable: true` fields and construct an implicit AND search query (`{ fieldA: {...}, fieldB: {...} }`) perfectly structured for the backend parameters.

```javascript
export default [
  {
    key: "name",
    label: "Name",
    searchable: true,
    type: "string", // Appends '{ name: { or: { like: searchValue } } }'
  },
  {
    key: "stock",
    label: "Stock",
    searchable: true,
    type: "number", // Appends '{ stock: { or: { eq: Number(searchValue) } } }' if searchValue is numeric
  },
  {
    key: "cost",
    label: "Cost",
    // Not searchable, to avoid conflicting logical search operators.
  },
];
```

The underlying helper function `buildTableSearchQuery` (from `map-methods`) will read this configuration and construct the correct query automatically.

## 3. Advanced Output Rendering (`renderCell`)

Whenever a particular cell requires complex formatting (such as converting raw digits strings into a currency string, injecting a clickable link, multiplying by a percentage, or assembling a mini-component), DO NOT write conditional rendering structures directly into the Page component or `<DataTable />`.

Instead, inject the `renderCell` method directly into your `table-source` config for that column:

```javascript
import { formatCurrency } from "../../controllers/globals";

export default [
  {
    key: "cost",
    label: "Cost",
    // Intercepts the raw 'cost' number and formats it globally
    renderCell: (val) => formatCurrency(val, "es-CO", "COP"),
  },
  {
    key: "website",
    label: "Domain",
    renderCell: (val, row) => (
      <a href={val} target="_blank">
        View Website
      </a>
    ),
  },
];
```

The underlying `<DataTable />` component natively understands `renderCell` and will yield total cell rendering control back to your callback function.

## 4. Dealing with Booleans and Object References

You must always pass your raw records retrieved from the API endpoints through the intelligent mapping functions (`fetchAndResolveTableData` or `resolveTableDataOptions`) before passing it to your DataTable's `data` prop.

These methods cross-reference your Form config arrays to intelligently format complex data sets:

- Translating raw database IDs located in arrays/strings directly into Human-readable Strings mapped from active backend dropdowns (`select: true`, `dynamicOptions`).
- Standardizing true/false values generated by `input: "boolean"` into `<FiCheck />` and `<FiX />` SVGs automatically with standard semantic colors (Var `--color-success`).

```javascript
// In your Page.jsx (Correct integration)
import { fetchAndResolveTableData } from "../../../config/controllers/map-methods";

const { records, count } = await fetchAndResolveTableData(
  apiMethods.GET_INGREDIENT_LIST,
  params,
  formFields, // The logic reads options from fields dynamically
);
setTableData(records);
```

## 5. Custom Column Styles (`styles`)

The base `<DataTable />` component aligns and centers all data globally via CSS. If a specific column requires a different alignment to improve readability (such as setting long descriptions to be left-aligned), you must use the `styles` property object.

The `<DataTable />` component natively parses and injects these styles directly into the corresponding `<th>` and `<td>` cells across that entire column without breaking standard table classes.

```javascript
export default [
  {
    key: "description",
    label: "Description",
    // Overrides global text-align: center cleanly without needing renderCell
    styles: { textAlign: "left", letterSpacing: "1px" },
  },
];
```
